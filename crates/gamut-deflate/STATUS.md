# gamut-deflate — DEFLATE / zlib encoder status

**v1 stabilization: GitHub issue #195.** A pure-Rust, space-efficient DEFLATE (RFC 1951) + zlib
(RFC 1950) **encoder** — the compression primitive `gamut-png` builds on (grown out of the PNG work,
issue #24). Built as small, individually green phases (each `mise run test`/`lint`/`fmt-check`/
`coverage` ≥ 80%, plus mutation testing).

**Keystone:** the bit-exact stored/fixed-Huffman + zlib-framing path (P-D2) — once that round-trips
through the reference inflater, every later phase swaps in a smarter block coder or parse behind the
same framing and Adler-32/FCHECK spine, with the oracle proving each step still decodes.

**Oracle:** differential vs the canonical C **zlib** (`tooling/zlib-oracle` + `third_party/zlib`,
dev-only FFI). gamut ships no inflater, so the gate is: inflate the encoder's output → byte-exact
with the input. The suite also asserts the ratio contract (`Level::Best ≤ zlib -9`, and
`Best ≤ Default`); `cargo bench` reports size + throughput against `miniz_oxide` and `zopfli`.

**Decoding is out of scope:** inflating DEFLATE is solved and security-sensitive; workspace decoders
that need it use `miniz_oxide`. See the crate docs' *Encoder only* / *Scope* sections.

## Phases

| Phase | Spec | Scope | Status |
| ----- | ---- | ----- | ------ |
| P-D1 | RFC 1950/1951 | Scaffold + workspace wiring + zlib-oracle/submodule; LSB `BitWriter`; Adler-32; zlib header (CMF/FLG/FCHECK); **stored blocks** (the always-correct floor) | ✅ done |
| P-D2 | §3.2.6 | Fixed-Huffman blocks (literals); per-input choice of stored vs fixed | ✅ done |
| P-D3 | §3.2.5, §4 | Length/distance symbol tables (exhaustive inversion tests); greedy hash-chain LZ77 matcher under fixed Huffman | ✅ done |
| P-D4 | §3.2.2, §3.2.7 | **Dynamic Huffman**: length-limited code build + canonical codes + code-length RLE (16/17/18); stored/fixed/dynamic min-cost selection; lazy matching → `Level::Default` | ✅ done |
| P-D5 | §4 | Cost-driven block splitting (recursive best-split) → `Level::Best` | ✅ done |
| P-D6 | — | **Optimal parse** (zopfli-style shortest-path DP + iterative entropy model) → `Level::Best` | ✅ done |

### Ratio (measured, zlib streams)

`Level::Best` beats `zlib -9` and `miniz_oxide`-10 on every measured input (~1–7% smaller); `zopfli`
is a few percent smaller again at a much higher, non-configurable cost. Full table in `README.md`;
the numbers are regenerated by `cargo test --test oracle` / `cargo bench`.

### Throughput (measured)

`Matcher::find` — the hash-chain longest-match loop, run up to `max_chain` (1024 at `Level::Best`)
times per input position — measures each candidate that survives its one-byte prune **eight bytes
at a time** (#478): both windows are read as a `u64`, the first differing byte is
`(x ^ y).trailing_zeros() / 8`, and the sub-word tail is compared byte-wise. Pure safe Rust, no
dependency, identical on every target, and byte-identical output — the same matches are found,
only measured faster; `tests/default_bytes.rs` pins the exact bytes at every level and passed
unchanged. Measured with `cargo bench -p gamut-deflate --bench compression` (divan, 100 samples
per row, on the 20 KB `references/png/rfc1950.txt` input; one machine, one session, the
byte-wise loop and the `u64` loop back to back, `after` being the first of two agreeing runs):

| Level              | before (fastest / median) | after (fastest / median) | throughput at fastest (time change) |
| ------------------ | ------------------------: | -----------------------: | ----------------------------------- |
| `Best`             |     24.36 ms / 30.05 ms   |     23.16 ms / 23.66 ms  | 841 → 885 KB/s (−4.9%) |
| `Default`          |    606.0 µs / 618.5 µs    |    566.3 µs / 577.2 µs   | 33.8 → 36.2 MB/s (−6.6%) |
| `Fast`             |    334.5 µs / 340.3 µs    |    315.1 µs / 322.7 µs   | 61.3 → 65.0 MB/s (−5.8%) |
| `Store`            |     5.17 µs / 5.19 µs     |     5.14 µs / 5.18 µs    | unchanged (no matcher) |

The `before` `Best` run was measured under contention (its median sits 23% above its fastest
sample, against 2% for the `after` runs), so its −21% median change overstates; the fastest column
is the honest comparison, and it puts the gain between 4.9% and 6.6% per level on this input. That is the shape one
would expect of prose: most chain candidates are rejected by the single-byte prune before the wide
compare runs at all, so the compare is a real but not dominant share of `find`, and the rest of the
per-position cost (the chain walk itself, hashing, and at `Best` the shortest-path DP) is untouched
by this change. The compare's share grows with the length of the matches actually found.

### Notes on D6

- The optimal parse spans the input in ≤ 1 MiB pieces
  (`DeflateEncoder::DEFAULT_OPTIMAL_PARSE_LIMIT`, overridable with `with_optimal_parse_limit`).
  Each span carries its own refined cost model and may reference the history before it, so encode
  cost grows linearly in the input while the dynamic program's working set stays bounded. Total
  input size never decides whether the parse runs (#343); before that it did, and inputs over
  1 MiB fell back to lazy + block splitting. A limit below the 32 KiB match window is raised to it:
  a shorter span would re-prime more history than it parses.
- Length-limiting uses the count-floor heuristic (within ~1% of optimal). A **package-merge** 15-bit
  limiter is an *optional* future refinement — it would narrow the remaining gap to `zopfli` but is
  not required for correctness or for the `Best ≤ zlib -9` contract.

## Notes / deferred

- **LSB `BitWriter`** is vendored here (ported from `gamut-webp`'s VP8L writer). An LSB writer now
  exists in two crates, so graduating a shared writer into `gamut-bitstream` (de-duplicating both) is
  a tracked follow-up; kept local for v1 to preserve the crate's self-contained, zero-internal-dep
  property.
- The public API surface (`DeflateEncoder`, `Level`, `adler32`) is stable from P-D1; later phases
  only improve the ratio, never change behaviour observable through the inflater. #337 grew it
  additively: `with_effort(u8)` exposes the optimal-parse pass budget (`DEFAULT_EFFORT = 6` keeps
  the default output byte-identical), and `Level` gained `#[repr(u8)]` with permanent
  discriminants per the workspace C-portability convention.
- `gamut-dng` now encodes its Deflate (`Compression = 8`) chunks with this crate and inflates with
  `miniz_oxide`, matching `gamut-tiff` and `gamut-png` (issue #196). Its whole-image-strip benchmark
  was the concrete case that motivated #343: a DNG written with `RowsPerStrip = ImageLength` hands
  the codec one multi-megabyte chunk, which used to skip the optimal parse entirely and leave
  `Level::Best` **0.6% larger** than `miniz_oxide`-6 on Adobe's `03_jxl_bayer_raw_integer.dng`. With
  the parse spanned it is 13 405 550 bytes against miniz-6's 13 423 208 — 0.13% smaller, same data,
  same level. One row is still adrift: `01_jxl_linear_raw_integer.dng` as a single strip is ~98.5%
  incompressible, and there `Best` lands 0.09% above miniz-6 (it wins by 0.5% tiled). On payloads
  with essentially no exploitable structure the optimal parse has nothing to find, which is a data
  property rather than a chunking one.
- **Full mutation survey** (`mise run mutants-crate gamut-deflate` — 546 mutants) is a tracked
  follow-up. It was deferred because the whole-crate local run was memory-hungry (cargo-mutants'
  parallel build copies); that is now bounded — the run derives its parallelism from a memory
  budget and is capped by a systemd scope, see [`docs/mutation-testing.md`](../../docs/mutation-testing.md) —
  so the survey is runnable and only the survivors below are outstanding. Known when it lands: the
  `adler32.rs` `| → ^` mutant in the `(s2 << 16) | s1` combine is *provably equivalent* (`s1` is
  always `< 2^16` and the low 16 bits of `s2 << 16` are zero, so `|` and `^` coincide) and will need
  a justified `exclude_re` carve-out rather than a test.
